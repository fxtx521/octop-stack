# Octop 瘦客户端 v0.1

Go 编写, 同一套代码编译 macOS / Windows。只调 Octop 官方 API（登录 + MCP 网关），不碰官方源码。

## 用法

纯对话模式:

    ./octop-client --url http://<云端地址>:<端口>

本地文件操作模式 (沙箱):

    ./octop-client --url http://<云端地址>:<端口> --ws ~/某个工作目录

按提示输入账号密码, 自动列出你的专家, 进入对话循环。
带 --ws 时, 专家能看到工作区文件清单; 它想读写文件时, 客户端弹审批, 你按 y 才执行。

## 沙箱安全设计

1. 路径只认相对路径, 绝对路径/..一律拒绝
2. symlink 展开后必须仍在工作区内, 否则拒绝
3. 每个操作单独校验, 一个被拒不影响其他
4. 未获用户批准, 一个字节都不写盘
5. 全部操作(含拒绝)留痕到工作区 .octop-audit.log (0600权限)

## 已验证 (2026-10-22, 隔离实例 8099)

- 登录 → 列专家 → 对话回答, 全链路通
- 员工账号只能看到自己的专家 (官方天然隔离)
- 访问他人专家返回 expert is not accessible
- 端到端: 专家生成操作计划 → 用户批准 → 文件真实落盘
- 拒绝场景: 按n后文件不落盘, 日志记 rejected
- 沙箱单元测试 10 项全过 (逃逸/symlink/审批/留痕)
- macOS (arm64) + Windows (amd64) 双构建通过
